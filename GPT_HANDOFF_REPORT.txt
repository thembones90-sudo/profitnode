1. PROJECT CONTEXT
======================================================================

PROFITNODE is a single-page browser application for a PC-flipping and
inventory ledger. It is branded as Shadezy Repair Shop.

Technical architecture:
- Vanilla JavaScript, HTML, and CSS.
- No backend, package manager, npm dependencies, bundler, or build step.
- Data is local-first and stored in localStorage.
- Primary storage key: profitnode_ledger_v1.
- Legacy fallback key: shadezy_ledger_v1.
- index.html is the HTML shell and contains the application CSS.
- pn_scripts.js is the canonical ordered runtime script manifest.
- app.js only streams the scripts from window.__PN_SCRIPTS with
  document.write(). This loading approach is intentional.
- app_core.js contains the core model, Store, Actions, rendering, and UI.
- Feature files ending in _extension.js append behavior to global objects.
- Script load order is critical.
- Runtime script changes require a matching cache-busting version change
  in pn_scripts.js.
- app.min.js must not be edited. The unminified files are production code.

The ledger shape includes:
meta, projects, inventory, deals, sales, timeline, plans, repairs, rigs,
roadTo, myRig, mail, and treasury.

Important sale/accounting rule:
- SOLD is a financial event, not a freely editable inventory status.
- Completed Sales Ledger rows drive dashboard REALIZED PROFIT.
- Treasury cash movements alone do not drive realized profit.
- A direct inventory sale must create one canonical completed sale row.
- SOLD inventory records remain stored for audit/history but are excluded
  from the default ACTIVE INVENTORY view.

3.4 ACTIVE / SOLD / TOTAL INVENTORY COUNTS
-----------------------------------------------------------------------

The Parts Vault filter bar now includes three compact live counters:
